# Marvis 投资地图 v4：从「数据仓库」到「作战地图」

> 日期：2026-11-25 ｜ 视角：操盘手 + 产品负责人 ｜ 性质：全新重构方案（本文件不改代码）
>
> 一句话：**先做减法，再做叠加。把 12 个数据页压成 1 张有主线的地图。**
>
> 这份方案不讨论"再加什么图"，而是先回答"为什么现在看不出来"。前几版方案的方向（叠加、相关性、体制）是对的，但执行方式错了：它们在 11 个面板之上又加了 5 个分析面板，结果是**信息更多、主线更少**。v4 的第一原则是**删**。

---

## 0. 十行结论

1. 现在的问题不是数据少，是**没有主线、没有同轴、没有"我的位置"**。
2. 12 个一级导航按"数据来源"分区（宏观/情绪/资金/技术/轮动），用户必须自己在脑子里拼接。
3. 单页最多 11 个面板、每张图配 3 行解读、字号从 9px 到 15px 有 9 档——这是"资料库"，不是"驾驶舱"。
4. 同一个 VIX 在 4 个地方有 4 套口径：绝对阈值 20/25/30 与历史分位混用，用户不知道信哪个。
5. 模块之间的"关系"目前靠底部 3 张文字卡片描述，图上完全看不到。
6. 真实数据、模型数据、模拟数据视觉权重相同，信任被稀释。
7. 新结构：**一条传导链 + 三层同轴图 + 一个动作清单**；导航 12 → 4。
8. 新图表语法：一次只显示一层、最多 6 条线、统一 Z 轴、相关性放独立条带、绝不用双轴。
9. 新数据策略：同一指标全站一个定义；只有快照的指标用**本地序列仓库**逐日累积成历史。
10. 成功标准不是"看了多少图"，而是**每周完成多少次"看地图 → 做/不做决定 → 记录"的闭环**。

## 1. 诊断：为什么"太乱"

### 1.1 用户原话翻译成产品问题

| 用户感觉 | 实际发生的事 | 产品问题 |
|---|---|---|
| "一堆数据，看不出啥跟啥" | 每页独立取数、独立归一化、独立时间范围 | 没有共享坐标系，无法比较 |
| "没脉络结构" | 模块按数据源划分，没有因果/传导顺序 | 没有叙事主线 |
| "没相关性" | 相关性只在一个小矩阵里，且用**价格水平**计算 | 关系没有被可视化，方法也有偏差 |
| "不知道有啥用" | 看完一页没有任何动作或结论 | 没有决策闭环 |
| "太乱了" | 12 个入口、面板堆叠、解释文字过载 | 没有信息预算 |

### 1.2 七个结构性问题（带代码证据）

**问题 1：按数据源分页，而不是按决策问题分页**

`src/shared/utils/constants.ts` 定义了 12 个一级 tab：简报、地图、节奏、纪律、持仓、资金流、宏观、情绪、做T、技术、轮动、告警。用户要回答"今天要不要动仓位"，至少要在 5 个页面之间跳转。页面边界是"我们有什么数据"，不是"用户要做什么决定"。

**问题 2：面板堆叠，没有信息预算**

- `src/modules/rhythm/RhythmPage.tsx`：11 个区块（体制卡、贡献分解、叠加图、相关矩阵、体制带、背离、指标时间线、今日三件事、事件日历、数据完整性、组合建议）。
- `src/modules/fundflow/FundFlowPage.tsx`：8 个区块。
- `src/modules/macro/MacroPage.tsx`：8 个区块。
- `src/modules/brief/BriefPage.tsx`：6 个区块。

每一块单独看都合理，合在一起就没有主角。用户的眼睛没有落点。

**问题 3：同一个指标，四套口径**

VIX 在代码里至少有四种解释：

- `src/services/macro.ts:71`：`vix > 30 ? critical : vix > 20 ? warning : normal`（绝对阈值）
- `src/services/optionsSentiment.ts:177`：`30 / 20 / 14` 三档（又一套绝对阈值）
- `src/shared/components/ModuleRelationshipFooter.tsx:63`：`30 / 20`（第三套）
- `src/modules/rhythm/services/rhythm.ts`：用 250 日历史分位（相对位置）

同一时刻，用户在四个页面会看到四种"VIX 高不高"的结论。这是"乱"的最直接来源。

**问题 4：关系靠文字，不靠图**

`ModuleRelationshipFooter.tsx` 在宏观、情绪、资金流、做T 四页底部各放 3 张卡片，用文字描述"VIX 上升会怎样影响情绪"。这些关系是**静态文案**，不随数据变化，也不在同一张图上呈现。用户被告知"有关系"，但看不到关系。

**问题 5：图表没有共享坐标**

- 有的图用绝对值（VIX 数值），有的用分位，有的用 Z-score；
- 时间窗口有 30 天、90 天、120 天、180 天、250 天；
- 没有十字光标联动，没有统一的"当前时间游标"；
- 月度序列和日度序列混画，只靠虚线区分。

结果：用户无法回答"这两条线是不是一起动"，因为它们从尺度到时间都不在同一个坐标系里。

**问题 6：真假数据混排，视觉权重相同**

- `src/services/fundflow.ts` 文件头写明"美股：结构化模拟"；
- `src/stores/useSectorRotationStore.ts` 是写死的演示轮动；
- `src/services/sentiment.ts` 的 A 股兜底用 seeded random 生成融资余额、北向、开户数；
- `src/modules/fundflow/components/DepthMap.tsx`、`OrderFlowTape.tsx` 是模拟盘口/逐笔。

这些数字和真实的 FRED 序列使用同样的字体、同样的颜色、同样的位置。用户一旦发现其中一个是假的，就会怀疑全部。**信任是产品体验的一部分，不是合规附属品。**

**问题 7：没有"我的位置"**

`map` 页是一个资产配置表单，`portfolio` 是一个独立页面，`rhythm` 讲市场，三者互不相通。用户看完"市场防守"，不知道"我的 78% 权益仓位算不算高"；看完"我的持仓"，不知道"这些持仓和当前主线是不是同一件事"。

### 1.3 量化体检

| 维度 | 现在 | v4 目标 |
|---|---|---|
| 一级导航 | 12 个 | 4 个 |
| 单屏可见面板 | 6~11 个 | 3 个（链、图、动作） |
| 每张图的解释文字 | 3 段（是什么/怎么看/不能怎么用） | 1 行读数；方法论收进"?" |
| 同一指标口径 | 最多 4 套 | 1 套（指标注册表） |
| 字号档位 | 9 档（9~15px） | 4 档（20/13/11.5/10） |
| 共享时间轴 | 0 | 全部图表共享 |
| 主路径模拟数据 | 4 处 | 0 处（全部标注或下线） |
| 从打开到"今天做什么" | ≥5 次点击、跨 3 页 | 0 次点击，首屏直接给出 |
| 最大叠加线数 | 8 条（全部指标） | 6 条，默认 4 条 |

### 1.4 为什么前几版方案没解决

前三份方案分别修可用性、修图表准确性、修产品体验，方向都对，但都掉进了同一个陷阱：

> **加法陷阱**：看到"用户看不出趋势和相关性"，就新增"风险温度叠加图 + 相关性矩阵 + 体制带 + 背离 + 事件日历"。
> 这些功能本身没错，但它们被**追加在原有 11 个面板之上**，没有替换任何东西。
> 结果是：用户要消化的信息从 100 增加到 160，主线仍然是 0。

v4 的顺序反过来：

1. **先删**：把 12 个页面里的重复、模拟、文字解释、伪关系全部拿掉；
2. **再并**：把剩下的真实能力压进 3 个决策层；
3. **最后加**：只加"能串起主线"的链、叠加、动作，不再加孤立面板。

### 1.5 病根一句话

> **这个产品把"数据分类"当成了"信息架构"，把"功能齐全"当成了"有用"。**
> 用户需要的不是更多指标，而是一条能从上看到下、从市场看到自己仓位的**主线**。

## 2. 重新定义产品

### 2.1 用户与 Job

| 维度 | 定义 |
|---|---|
| 是谁 | 有 5~50 万美元 / 50~300 万人民币可投资资产，自认为主动投资者，每天愿意花 10~30 分钟 |
| 会什么 | 懂基本概念（VIX、利差、均线），但不会写代码、不建模型 |
| 核心 Job | **"今天我要不要动？动哪里？动多少？"** |
| 次要 Job | "我现在的持仓，和当前市场主线是不是一回事？" |
| 失败恐惧 | 在错误的环境里下重注；看似分散实则同向；情绪化交易后无法复盘 |
| 他不需要的 | 更多行情、更多新闻、更多指标堆砌、买卖点喊单 |

### 2.2 "投资地图"到底是什么

不是把市场画成一张地理图，而是让用户一眼看到三件事：

> **我在哪（位置）→ 周围地形如何（环境与结构）→ 下一步往哪走（动作）。**

对应产品结构：

```
一条链：资金价格 → 风险定价 → 人群行为 → 结构轮动 → 我的位置
三层图：环境层（天气） / 结构层（道路） / 我方层（我的位置）
一个动作：今日 0~3 件事（检查 / 调整 / 记录），永不给买卖点
```

- **链**解决"看不出啥跟啥"：把传导顺序画出来，每一环显示读数、方向、与下一环的历史同步性。
- **层**解决"没脉络"：同一时间轴下，从环境到结构到仓位逐层下钻，一次只看一层。
- **动作**解决"有啥用"：每条动作都由可见的数据规则触发，可解释、可记录、可复盘。

### 2.3 三条设计原则

1. **结论先行，证据后置。**
   首屏第一行必须是"今天怎么样、要不要动"，而不是一张图。图是证据，不是主角。
2. **同轴才可比，单轴才诚实。**
   所有叠加统一到 Z-score / 分位 / 重定基 100 三种尺度之一；相关性单独一条 -1~1 的条带，共享 X 轴；**永远不用双 Y 轴**。
3. **一个指标只有一个真相。**
   同一指标全站只允许一个定义、一个读数、一个更新时间。页面不能各自计算。

### 2.4 明确不做什么

- 不做买卖信号、目标价、收益预测、仓位"建议买入"。
- 不做新闻流、社交、股吧、直播。
- 不为了"丰富"新增一级导航。
- 不做超过 6 条线的叠加图。
- 不用双轴制造虚假相关。
- 不用随机数/写死值填充主路径；取不到就显示"不可用"。
- 不做自动交易。

## 3. 新信息架构

### 3.1 四个一级入口

| 入口 | 回答的问题 | 内容 |
|---|---|---|
| **地图**（默认） | 今天怎么样？我要不要动？ | 状态条 + 传导链 + 三层图 + 读数栏 + 今日动作 |
| **研究** | 为什么？让我自己验一下 | 叠加实验室、相关性实验室、事件研究、板块 RS、数据血缘 |
| **决策** | 具体怎么安排钱和仓位？ | 配置计划、仓位/风险预算、持仓与暴露、观察清单、复盘日志 |
| **档案** | 这些数字可信吗？我以前怎么做的？ | 指标字典、数据来源、决策历史、使用复盘、设置 |

顶栏只保留：Logo、4 个入口、市场切换、数据时间、刷新。**不再放 12 个带两行副标题的按钮。**

### 3.4 首屏信息预算（硬约束）

- 1 句结论，不超过 60 字；
- 1 条链，5 个节点；
- 1 张图（一次只显示一层），不超过 6 条线；
- 5 张读数卡，每张不超过 3 行；
- 0~3 条动作，每条不超过 2 行；
- 首屏不出现：KPI 大数字墙、新闻、解释性长文、第二个图表。

## 4. 主屏「今日地图」

### 4.1 状态条（首屏第一行）

格式固定，三件事：

```
今天：{体制} · 风险温度 {R}/100（{分位}）· {一句变化} · {动作结论}
```

示例：

```
今天：防守 · 风险温度 64/100（78% 分位）· 信用利差走阔、VIX 未跟 · 今日无需交易
```

- 数据不可用时整行变橙：`今天：数据不可用（上游未返回），不给判断`。
- 置信度 < 50% 时在末尾加 `· 置信度偏低`。
- 不写"建议买入/卖出"，只写"无需交易 / 检查偏离 / 检查集中度 / 记录"。

### 4.2 传导链（核心组件）

这是解决"没脉络"的主结构。五个节点从左到右，代表资金与风险的传导顺序。

#### 节点定义

| 节点 | 读什么 | 组成 | 回答 |
|---|---|---|---|
| **A 资金价格** | 钱贵不贵 | DGS10、DTWEXBGS、EFFR（CN 用 CN10Y + 汇率） | 流动性在收还是在放？ |
| **B 风险定价** | 风险贵不贵 | HY OAS、VIX、T10Y2Y（反向） | 市场为风险付的价格在升吗？ |
| **C 人群行为** | 人挤不挤 | FG、Put/Call、融资余额（仅真实时） | 情绪是否走到极端？ |
| **D 结构轮动** | 钱往哪走 | 板块 RS 离散度、市场宽度、主力净流入 | 是普涨/普跌，还是结构行情？ |
| **E 我的位置** | 我站哪 | 权益仓位 vs 目标、Beta、集中度 HHI、与基准相关性 | 我的暴露和当前环境匹配吗？ |

每个节点是一张固定高度的小卡（约 96px）：

```
┌─────────────────────────┐
│ 风险定价          ● 真实 │
│ 68 / 100   ↑ 20日 +6    │
│ ▁▂▃▅▆▅▇  (60日迷你线)   │
│ 信用利差走阔 · 波动未跟   │
└─────────────────────────┘
```

- 大数字是**近一年分位**，不是绝对值；绝对值放 hover。
- 方向箭头是 20 日变化，不是当日涨跌。
- 状态标签只有五种：正常 / 偏高 / 极端 / 背离 / 数据不足。
- 来源点：绿=真实、蓝=模型、灰=不可用。**没有"示例"混在主路径。**

#### 箭头（关系）

箭头不是装饰，是数据：

```
A ── 0.41 ── B
```

- 数值 = 两节点代表序列的 **60 日滚动相关**，用**变化率**计算（价格用对数收益，利率/利差用一阶差分），不是价格水平。
- 颜色：正相关用暖色，负相关用冷色；|r| < 0.2 显示灰色虚线并标注"弱关联"。
- 如果当前相关性与一年中位数**符号相反**，箭头变橙并标注"关系翻转"。
- 点击箭头 → 打开"研究"里的该对叠加预设（主图 + 相关性条带 + 领先滞后）。
- 图例必须写一句：**"历史同步性，不代表因果。"**

#### 链路叙事

链路下方给一行"人话翻译"，由规则生成，例如：

```
钱在变贵（美元 +1.2σ）→ 信用还没明显走阔 → 人群已偏谨慎 → 结构上资金集中在防御 → 你的仓位仍偏进攻
```

这行话是整张地图的"主线"，不是每张图各说各话。

#### 交互

- 点击节点：下方三层图自动切到该节点对应的层，并预选相关序列。
- 点击箭头：进入研究模式，预加载两条序列。
- 数据不足的节点：卡片变灰，链路断开处显示"缺"，不假装连通。
- 窄屏：链改为纵向，箭头旋转 90 度，语义不变。

### 4.3 三层同轴图

只显示一层，用分段控件切换。每层只有一张主图，图下只有一行读数。

#### L1 环境层（天气）

- **主图**：4~6 条 Z-score 线（VIX、HY OAS、DXY、10Y、-T10Y2Y、FG 极端度），250 日滚动 Z。
- **背景**：体制色带（进攻/均衡/防守/观望），颜色低饱和，不抢线。
- **标记**：背离点（信用-波动、价格-信用、情绪-价格）。
- **读数行**：`4 项中 3 项同向偏风险 · 信用领先、波动未跟（背离 +0.9σ）`。
- **默认窗口**：1Y；可切 3M/1Y/3Y。

#### L2 结构层（道路）

- **上半**：3 条相关性条带（SPX-TLT、DXY-SPX、HY-VIX），各自 -1~1，共享 X 轴，0 线加粗。
- **下半**：板块 RS 发散条（前 5 / 后 5）+ 市场宽度线。
- **读数行**：`股债相关性 30 天由 -0.3 转 +0.2 · 分散化减弱 · 强势集中在 3 个板块`。
- 没有真实板块数据时：只显示相关性条带，板块区显示"数据不足"，不填充演示值。

#### L3 我方层（我的位置）

- **主图**：组合净值 vs 基准，重定基 100；回撤阴影；体制色带。
- **叠加**：目标权益带（例如 70%±5pp）作为横向参考条，当前位置一个点。
- **读数行**：`权益 78%（目标 70%±5）· 前三大持仓 61% · 与基准 60 日相关 0.86`。
- 没有持仓时：显示空状态"录入持仓后显示"，并提供"用示例组合看一遍"的明确按钮（示例态必须有水印）。

#### 为什么一次只显示一层

三层同时出现 = 三张图 + 三套坐标 = 回到现在的混乱。一次一层，靠"链"保持上下文，靠"切换"下钻。这是本方案与前三版最重要的体验差异。

### 4.4 读数卡（替代长文案）

动作不是推荐，是**基于可见规则的检查项**。最多 3 条，按优先级排序。

| ID | 触发条件 | 动作文案 | 类型 |
|---|---|---|---|
| R1 | 当前体制 ≠ 上次记录体制 | 体制已切换，检查单笔风险预算是否仍按旧体制设定 | 检查 |

## 5. 图表叠加系统（本方案的心脏）

### 5.1 视觉语法（硬规则，写进组件，不靠自觉）

1. **一张图只回答一个问题。** 标题是问题或结论，副标题是一行读数。
2. **Y 轴只有一种尺度**：Z-score（叠加不同量级）、分位（0~100）、重定基 100（价格比较）三选一。
3. **绝不用双 Y 轴。** 相关性、成交量、回撤一律放独立条带，共享 X 轴。
4. **最多 6 条线，默认 4 条。** 超过 6 条必须拆图或让用户取消。
5. **线型编码相位**：实线=同步，虚线=领先，点线=滞后；不能只靠颜色。
6. **右侧直接标注末值**，减少"图例-线"来回找。
7. **图例即开关**：点击隐藏/单独显示；双击 solo。
8. **缺失就是缺失**：断线 + 斜纹 + "缺"字，不静默插值；月度序列前向填充时必须画点线并标注。
9. **注释不超过 2 层**：一层体制/事件色带，一层关键标记（背离/极端）。不叠加箭头、气泡、文字墙。
10. **颜色语义分离**：
    - 价格涨跌：红涨绿跌（A 股习惯），必须带文字标签；
    - 风险高低：蓝（低）→ 橙（高）顺序色，不用红绿；
    - 相关性：蓝（负）→ 灰（0）→ 红（正），格子里必须带数字。
11. **性能**：单图 ≤ 600 点，canvas 渲染；1 万点以上先降采样。
12. **文字预算**：图下最多 1 行读数；方法论进"?"抽屉。

### 5.2 组件与数据契约

只做一个叠加图组件，所有页面复用，避免每个页面各写一套 Chart.js 配置。

```ts
type Scale = 'z' | 'percentile' | 'rebased';

interface OverlaySeries {
  id: string;
  label: string;
  values: (number | null)[];
  scale: Scale;
  color: string;
  phase?: 'leading' | 'coincident' | 'lagging';
  source: 'real' | 'model' | 'unavailable';
  dash?: 'solid' | 'dashed' | 'dotted';
}

interface OverlayBand {
  from: string;
  to: string;
  color: string;
  label?: string;
}

interface OverlayMarker {
  date: string;
  label: string;
  kind: 'event' | 'divergence' | 'extreme';
}

interface ChartSpec {
  dates: string[];
  series: OverlaySeries[];
  bands?: OverlayBand[];
  markers?: OverlayMarker[];
  corrStrip?: { aId: string; bId: string; window: number };
  yDomain?: [number, number];
  height?: number;
}
```

- `dates` 由统一快照生成，所有图共享；
- 相关性条带由组件内部按 `aId/bId` 计算，使用**变化率**并对齐交集日期；
- 任何序列 `source === 'unavailable'` 时，组件显示灰线断点 + "缺"，并在右上角显示"缺 N 条"。

### 5.4 相关性三件套

相关性不能只给一个数字，要给三个视角：

#### (1) 相关性矩阵

- 输入：收益率/变化率，不是价格水平。
- 窗口：20 / 60 / 120 日可切。
- 排序：按聚类排序（相关高的放一起），不要按字母。
- 颜色 + 数字同时显示；对角线固定 1；样本不足显示"—"。
- 重点不是"谁和谁相关"，而是**哪些格子在变**：与 60 日前对比，变化 > 0.35 的格子加边框。

#### (2) 滚动相关性条带

- 一次只选一对（例如 SPX-TLT），画 120 日滚动相关。
- 条带自己的 Y 轴是 -1~1，放在主图下方，共享 X 轴。
- 画一条 0 线；再画一条"近一年中位数"虚线。
- 符号翻转处打标记："30 天内由 -0.3 转 +0.2"。
- 加一句读数："分散化正在减弱" / "恢复" / "不稳定"。

#### (3) 领先-滞后交叉相关

- 对两条序列的变化率，计算 lag = -30…+30 的相关系数。
- 画一条滞后-相关曲线，标出峰值 lag 和峰值相关。
- **稳定性检查**：把样本切成前后两半，峰值 lag 相差 > 10 天则标注"不稳定，别当规律"。
- 只在峰值 |r| > 0.3 时给出文字结论；否则只显示曲线，不给解读。

#### 方法说明（必须写进 UI 的"?"）

- 价格用对数收益，利率/利差用一阶差分；用水平值算相关会被趋势主导，产生虚假高相关。
- 对齐用日期交集，不用前向填充；月度序列不进入日度相关矩阵。
- 重叠窗口会让显著性被高估；本产品只做描述，不做"显著/不显著"的统计承诺。
- 相关不等于因果；相关性会漂移；极端行情下线性相关会失真（可切 Spearman）。

### 5.5 事件研究（进阶，但很实用）

- 选择事件类型：FOMC、CPI、非农、期权到期、财报窗口（只使用**可确认日期**，不编造）。
- 以事件日为 T0，取 T-20 ~ T+20 的窗口。
- 把过去 N 次同类事件对齐，画：
  - 中位数路径（粗线）；
  - 25%~75% 分位带（浅色）；
  - 本次路径（高亮）。
- 回答："历史上这类事件前后，市场通常怎么走？这次是否不一样？"
- 必须标注样本数 N；N < 5 时只显示"样本太少"。
- 不做"这次一定怎样"的结论。

### 5.6 性能与降级

- 所有数据进内存前先按日期排序、去重、限制 1000 点。
- 叠加图统一用 canvas；切换层不重新请求，只重绘。
- 计算相关性/分位用 memo，按 `seriesVersion + window` 缓存。
- 上游失败时保留上一次成功快照，标注"缓存数据 · 11-24"，超过 3 个交易日则禁用结论。

## 6. 指标体系：从"绝对值"到"可决策读数"

### 6.1 指标分层

| 层 | 指标 | 用途 | 是否进首屏 |
|---|---|---|---|
| 领先 | HY OAS、T10Y2Y、美元、油价 | 预警，先动 | 是（链 B/A） |
| 同步 | VIX、10Y、指数、宽度 | 确认当下 | 是（链 B/D） |
| 情绪 | FG、Put/Call、融资余额 | 极端与拥挤 | 是（链 C） |
| 滞后 | CPI、失业率 | 事后确认，不择时 | 否（研究层） |
| 结构 | 板块 RS、相关性、离散度 | 钱往哪走 | 是（链 D） |
| 我方 | 仓位、Beta、HHI、回撤、相关 | 我站哪 | 是（链 E） |

### 6.2 九个核心读数（全站只用这一套）

| 读数 | 定义 / 公式 | 展示 | 常见误读 |
|---|---|---|---|
| **风险温度 R** | 加权 Z 合成分，再取近一年分位 | 0~100 + 分位条 | 不是"下跌概率"，只是环境温度 |
| **信用脉冲 C** | Δ20 日 z(HY OAS) | +/− σ，正=走阔 | 走阔不等于马上跌，可能持续很久 |
| **波动压力 V** | z(VIX)，有期限结构时叠加 VIX/VIX3M | Z + 分位 | 低波动不等于低风险 |
| **流动性潮汐 L** | z(DXY) + z(10Y)，方向取"钱变贵"为正 | Z | 利率上行也可能来自增长 |
| **情绪极端 E** | \|FG−50\|/50，0~1 | 0~1 + 文字 | 极端可以更极端，不能逆势重仓 |
| **市场宽度 B** | 上涨家数 /（上涨+下跌），或等权/市值权 20 日差 | 0~100 | 指数涨不代表多数股票涨 |
| **轮动强度 RS** | 板块 20 日超额收益 / 60 日跟踪误差 | 排名 + 条 | 强不代表会继续强 |
| **相关性体制 K** | 60 日 corr(SPX, TLT) 的近一年分位 | 0~100 | 相关性会突变，历史分位不是保证 |
| **我的偏离 D** | 权益实际 − 目标；Beta；HHI；与基准相关 | pp / 数值 | 偏离不是错，超阈值才需要检查 |

### 6.3 复合指标公式（v1 固定，权重可见）

```
z_i = 250 日滚动 Z-score
E   = |FG − 50| / 50

风险温度原始值 =
  0.25 * z(HY OAS)
+ 0.20 * z(VIX)
+ 0.15 * z(DXY)
+ 0.15 * (−z(T10Y2Y))
+ 0.10 * z(DGS10)
+ 0.15 * E

R = 近一年分位(风险温度原始值) × 100
```

- 权重在"?"里公示，不做黑箱；v1 不允许用户改，避免过度拟合。
- 缺失指标时按剩余权重归一化，并显示"覆盖 5/6，置信度下降"。
- 所有 Z 值都用滚动窗口，**不使用全样本均值/标准差**（避免未来函数）。

背离：

```
信用-波动背离 = Δ20z(HY OAS) − Δ20z(VIX)
> +0.8  → 信用先走、波动未跟（警示）
< −0.8  → 波动先走、信用未跟（可能是情绪冲击）
```

### 6.4 单一定义原则（Metric Registry）

新建 `metrics/registry.ts`，每个指标只定义一次：

```ts
interface MetricDef {
  id: string;
  name: string;
  unit: string;
  precision: number;
  frequency: 'daily' | 'monthly';
  source: 'fred' | 'fng' | 'eastmoney' | 'cboe' | 'local';
  phase: 'leading' | 'coincident' | 'lagging' | 'sentiment';
  transform?: 'yoy' | 'diff' | 'logret';
  normalize: 'z250' | 'pct252' | 'rebased';
  higherIsRisk?: boolean;
  description: string;
  howToRead: string;
  pitfall: string;
}
```

规则：

- 所有页面从同一个 `useSnapshot()` 取数，不各自 fetch、不各自算分位。
- 同一指标在图、卡、动作里必须是同一个数字；如果不一致，以 registry 为准并修页面。
- 删除 `macro.ts` 里的绝对阈值判断（VIX>30 等），统一改为分位/状态。
- 指标的"解释/怎么看/误读"只存在 registry 里，UI 通过"?"读取，不再复制到每个组件。

### 6.5 缺失与降级

| 缺失程度 | 行为 |
|---|---|
| 单条缺失 | 该线断开标"缺"，复合指标按剩余权重算，置信度下降 |
| 关键两条缺失 | 链对应节点灰掉，状态条标"置信度低"，动作区不触发相关规则 |
| 全部缺失 | 整页"数据不可用"，不给判断，不用缓存假装实时 |
| 数据过期 > 7 天 | 结论降级为"参考"，动作区只保留"检查数据源" |

### 7.2 本地序列仓库（解决"只有快照，没有历史"）

这是让 A 股宽度、板块资金流、组合净值能进入叠加分析的关键，也是"数据越用越多"的机制。

- IndexedDB 新增 `series_daily` 表：`{ seriesId, date, value, source, meta }`，主键 `[seriesId, date]`。
- 每个交易日首次打开（或 30 分钟轮询时）写入当天快照：
  - `breadth_ratio`（涨跌家数比）
  - `sector_flow_<code>`（板块主力净流入）
  - `sector_rs_<code>`（由板块 K 线算，可回溯）
  - `portfolio_value`（组合净值）
  - `fg`（已有历史，但可统一入库）
- 不做虚假回填：没有就是没有。UI 显示"已积累 12/20 个交易日，满 20 天可算相关性"。
- 保留 3 年；数据量极小（每天几十条）。
- 支持导出/导入 JSON，跟持仓一样存本机。
- 派生能力：
  - 20 天后：宽度与指数相关性、资金流与 RS 相关性；
  - 60 天后：组合 Beta、组合与基准相关、持仓两两相关；
  - 120 天后：相关性体制分位、轮动持续性。

**产品话术**：不是"我们数据不够"，而是"从今天开始，你自己的地图会越来越清楚"。

### 7.3 可新增的真实序列（大多不用改后端）

| 来源 | 候选序列 | 用途 |
|---|---|---|
| FRED via /convex | SP500、VXVCLS（VIX3M）、DCOILWTICO、BAA10Y、T5YIE、DFII10、NFCI、UMCSENT | 信用、波动期限、实际利率、金融条件 |
| Yahoo（已有 yahooApi） | SPY、QQQ、TLT、IWM、GLD、USO、XLK/XLF/XLE 等板块 ETF | 美股 RS、股债相关、利率-成长 |
| 东财 push2his | 板块指数、个股日 K（250 根） | A 股 RS、个股 vs 基准、持仓相关 |
| CBOE | Put/Call、VIX 期限结构 | 情绪与波动结构 |
| 本地仓库 | 宽度、资金流、组合净值 | 把快照变成历史 |

接入原则：

- 先验证返回长度 ≥ 60，再进 UI；
- 每个新序列必须在 registry 注册，带 source/phase/frequency；
- 首屏最多 6 条，研究层可以多，但不能默认全开。

### 7.4 数据血缘（信任的最后一公里）

任何数字点开"?"，都能看到：

- 来源（FRED / 东财 / CBOE / 本地）
- 序列 ID 与口径（水平值/同比/差分）
- 最新日期与样本长度
- 归一化方法（Z250 / 分位 / 重定基）
- 缺失情况与置信度
- 最近一次抓取时间

"档案 → 数据血缘"提供全量列表和健康状态（正常/延迟/失败），让用户能自己判断该不该信。

## 8. 从"看"到"做"：四个闭环

数据只有落到动作和复盘，才叫"有用"。

### 8.1 体制 → 风险预算（最短的一条路）

- 把当前 `tone` 传给仓位计算器：
  - 进攻/均衡：默认单笔风险 2%
  - 防守：默认 1%
  - 观望：默认 0.5%，并提示"暂停新开仓"
- 显示"因为当前是防守态，默认值已下调；你可以改，但要知道为什么"。
- 只调风险预算，不给买卖点，完全合规。
- 复盘时记录"当时的体制"，事后能看"防守态下我是否更容易破规则"。

### 8.2 相关性 → 分散化检查

- 用本地仓库的持仓收益（或真实 K 线）算两两 60 日相关。
- 输出：
  - 平均两两相关；
  - 最高的 3 对（> 0.8 标红）；
  - "有效持仓数"（1 / HHI 或相关矩阵特征值，v1 先用 HHI 近似）。
- 文案："你持有 6 个标的，但平均相关 0.82，实际更像 2 个仓位。"
- 不给"卖哪个"，只给"检查"。

### 8.3 轮动 → 观察清单（不是买入）

- 强势板块加入 watchlist，附带触发条件：
  - RS > 0 持续 10 日；
  - 主力净流入连续 3 日为正；
  - 与基准相关性下降（走独立逻辑）。
- 触发时进"今日动作"的"留意"区，不直接说买。
- 观察清单有"为什么加、当时读数、触发条件"，事后可回看判断质量。

### 8.4 复盘 → 决策快照与归因

- 每次 `[记录决定]` 自动写入：
  - 当时体制、风险温度、5 个节点读数；
  - 组合权重、权益偏离、集中度；
  - 本次动作（检查/调整/记录/不动）与理由。
- 季度回看（不是盈亏报告）：
  - 在防守态做了多少次主动加仓？
  - 有多少次操作是计划内的？
  - 哪些规则最常被违反？
- 这是产品真正的差异化：**复盘决策质量，而不是晒收益。**

## 10. 路线图与验收

> 顺序原则：先删后加；先统一读数，再谈分析；先做能回答"今天做什么"的，再做"更专业"的。

### P0 清场与统一（3~4 天）

**交付**

- 设计令牌：4 档字号、3 种间距、2 套颜色语义（价格/风险）。
- 指标注册表 + 统一快照 store：同一指标全站一个读数。
- 相关性改为收益率/一阶差分；月度序列不进入日度相关。
- 主路径移除随机/写死数据；所有数字加来源点。
- 删除 `ChartInsight` 主路径用法、`ModuleRelationshipFooter` 用法。
- 首屏信息预算落到组件约束。

**验收**

- 全站搜索不到主路径 `Math.random` 兜底；
- 同一指标在任意两页读数一致；
- 首屏面板 ≤ 3；
- `npm run build` 通过。

### P1 地图首屏（1 周）

**交付**

- 4 个一级入口 + 顶栏重做。
- 今日地图：状态条、传导链、三层图（环境/结构/我方）、读数栏、动作区。
- 无动作状态、数据不可用状态、无持仓状态。
- 旧页面暂时保留在"研究"里做迁移，不直接删代码。

**验收**

- 新用户/老用户打开 30 秒内能说出"今天要不要动"；
- 首屏不需要滚动就能看到结论 + 链 + 图；
- 窄屏链纵向可用；
- 所有缺数据处显示"缺"，无演示值。

### P2 叠加实验室（1.5~2 周）

**交付**

- `OverlayChart` + `CorrelationStrip` 统一组件。
- 5 个首批配方：风险温度、美元潮汐、情绪-价格、板块 RS、组合 vs 基准。
- 相关性三件套：矩阵（收益率）、滚动条带、领先滞后。
- 事件研究（可选，若时间紧放 P3）。
- "?"数据血缘抽屉。

**验收**

- 任意两条真实序列 ≤ 3 次点击可叠加；
- 相关性结果与手算一致（抽查 3 组）；
- 12 个配方全部有明确数据状态（可用/需接/需攒），不出现"看起来能算其实是假数"。

### P3 闭环（1 周）

**交付**

- 动作引擎 R1~R8 + 记录决定。
- 体制 → 仓位计算器默认值联动。
- 观察清单（条件式）+ 告警。
- 复盘自动快照 + 季度决策质量报告（v1 先做简单统计）。

**验收**

- 每条动作都能点回触发它的数据；
- 记录一次决定后，档案里能看到当时的 5 个读数；
- 连续一周至少完成 1 次"看→决定→记录"闭环（自测）。

### P4 清理与迁移（3 天）

**交付**

- 旧 12 tab 的路由重定向/归档。
- 删除确认无用的模拟组件与 store。
- 数据血缘页、指标字典、使用复盘。
- 文档与 README 更新。

**验收**

- 无死链；无重复指标定义；
- 包体积不增大（删多于加）；
- 新用户首次路径 ≤ 3 分钟。

### 风险与对策

| 风险 | 对策 |
|---|---|
| 上游数据不稳定 | 保留上次快照 + 明确标注时间；关键结论要求新鲜度 |
| 指标越加越多 | 首屏硬上限 6 条线、4 个入口；新指标只能进研究层 |
| 用户想要"更多功能" | 用"配方"扩展，不新增页面；配方是同一组件的预设 |
| 相关性被误读为因果 | 链上固定文案"历史同步性，不代表因果"；研究层给方法说明 |
| 旧页面迁移遗漏 | P4 前保留路由，逐页对照功能清单 |

## 11. 成功指标

### 北极星指标

> **每周完成的"看地图 → 做/不做决定 → 记录"闭环次数（WAC）。**

## 12. 边界与合规

- **只描述，不预测**：所有结论是"当前处于什么位置、历史上类似位置发生了什么"，不是"接下来会怎样"。
- **不给买卖信号/目标价/收益承诺**：动作只有"检查/调整/记录/不动"。
- **不编造数据**：取不到就"不可用"；模拟数据只能出现在明确水印的示例态。
- **不用双轴制造虚假相关**：统一尺度 + 独立相关条带。
- **相关性声明**：历史同步性不等于因果；相关性会漂移；样本不足时不解读。
- **风险提示**：常驻页脚，不遮挡但不消失。

## 附录 C：术语表

| 术语 | 含义 |
|---|---|
| Z-score | 当前值相对滚动窗口均值偏离多少个标准差 |
| 分位 | 当前值在近一年样本中的位置（0~100） |
| 重定基 100 | 把两条价格序列起点都设为 100，比较相对涨幅 |
| 滚动相关 | 用固定窗口逐日计算两条序列变化率的相关系数 |
| 领先/同步/滞后 | 指标相对经济/市场的经验时序位置，不是精确承诺 |
| HHI | 持仓权重平方和，衡量集中度 |
| 有效持仓数 | 1/HHI 的近似，表示"相当于几个独立仓位" |
| 背离 | 两个历史上同向的指标，近期方向不一致 |
