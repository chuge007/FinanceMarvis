# Marvis·投资地图 —— 让普通人真正用起来的优化方案

> 版本：2026-11-24 ｜ 性质：**方案（未改动任何源码）** ｜ 方法：全量只读代码审计 + 逐条证据核实
>
> 这份方案取代 `docs/` 下 StrategyLab 时代的旧规划（那些面向"操盘手"，指标被显著高估，与当前产品定位不符）。

---

## 0. 结论先行

这个产品的**内核（投资地图 + 市场节奏 + 纪律复盘）质量高于它自己 README 的描述**——合规克制、逻辑自洽、真正站在普通人一边，市面上少见。

但它离"普通人真能用起来"，卡在**三条信任崩塌级硬伤**上：

| 硬伤 | 用户感知 | 本质 |
|---|---|---|
| 告警永不触发 | 设了"跌破提醒"却永远收不到通知 | 触发函数写好了，没人调用 |
| 持仓盈亏是死的 | 现价靠手填，几天后盈亏全是错的 | 刷新函数写好了，没人调用 |
| 换台电脑数据全丢 | 清浏览器缓存 = 画像/持仓/复盘归零 | 数据只进本机，没有导出/导入 |

**核心判断：不需要重做功能，只需要"把已经写好的函数接上线、把数据留住"。** 三项 P0 投入都小（合计约 2-3 人日），但价值提升最大。先做这三件，产品就从"看起来能用"变成"真的能用"。

## 1. 现状诊断

### 1.1 产品定位（取自根目录 README）

给普通人的投资决策流程工具：先决定"多少钱可以进股市"，再决定"怎么放、放多少、什么时候调"。不荐股、不给目标价、不预测收益。

### 1.2 架构速览

```
浏览器 React 19 + TS + Zustand + Vite（src/main.tsx → App.tsx 单页 tab 切换）
├── 核心内核（新，质量高）
│   ├── modules/map/        投资地图：画像→四桶分钱→比例规则→六件可操作事项
│   ├── modules/rhythm/     市场节奏：8 个真实宏观序列算历史分位→风险状态
│   └── modules/discipline/ 纪律复盘：仓位计算器/下单6问/再平衡/复盘日志
├── 遗留外壳（旧，多为演示/死代码）
│   ├── portfolio 持仓 / alerts 告警   —— 有 store 无接线

```

### 1.3 审计纠偏（体检代理的两处误判，已逐行核实）

严谨起见，先纠正自动审计报告里两处与代码不符的结论，避免方案建立在错误前提上：

| 审计说法 | 核实结果 | 证据 |
|---|---|---|
| "rhythm 写入的 regime key 可能永远是空，discipline 读不到" | **错误**。regime 状态确实写入 | `RegimeCard.tsx:43-46` 在 `useEffect` 里 `writeJSON(KEY,...)`；`DisciplinePage.tsx:11` 正常读取 |
| "复盘日志没有导出功能" | **错误**。复盘日志已有"导出"按钮 | `Journal.tsx:47-55` 有 `exportJSON()`，UI 上有导出按钮 |

> 修正后的真实缺口是：**只有复盘日志能导出，画像/持仓/告警都不能；且全项目没有任何"导入"能力**。这比"完全没导出"轻，但仍不足以支撑"换设备不丢数据"。

## 2. 缺口清单（按对普通人的伤害排序）

### P0 · 信任崩塌级（必须先修）

#### P0-1 告警永远不会触发
- **症状**：用户设"贵州茅台跌破 1400 提醒"后高枕无忧，实际永远收不到。
- **证据**：`useAlertStore.ts:115-185` 定义了完整 `checkAlert()`（含触发判断、写库、桌面通知、声音），但全项目搜索 `checkAlert` 只有定义处，**无任何调用点**；`AlertPage.tsx` 只调 `loadAlerts()`。README.md:87 已自认。
- **附带缺陷**：通知图标 `/icon.png`、声音 `/alert.mp3` 在 `public/` 和 `dist/` 均不存在（只有 favicon/icons 两个 svg），即使接上也会 404。

#### P0-2 持仓现价永不更新，盈亏是"死的"
- **症状**：买入时手填现价，之后价格不动，`dayPnL` 恒为 0、胜率恒为 0、现金永远 10 万。
- **证据**：`usePortfolioStore.ts:143-162` 有 `updatePrice()`、`:164` 有 `executeTrade()`，均无调用点；`currentPrice` 只在添加时手填且 UI 无修改入口；`:265-268` 明文写着 `dayPnL: 0 // 需要昨日收盘价，暂时设为0`、`winRate: 0 // 需要根据历史交易计算`。

#### P0-3 数据只存本机且无完整备份/导入
- **症状**：换电脑、清缓存、重装系统 = 全部记录归零。
- **证据**：画像/复盘走 `localStorage`（`localStore.ts:1-19`，配额满还静默降级），持仓/告警/交易走 IndexedDB（`storage/indexedDB.ts` 无 export 方法）。全项目仅 `Journal.tsx` 一个局部 JSON 导出，**无导入、无整体备份**。README.md:90 已列为已知限制。

### P1 · 使用门槛级

#### P1-4 首次使用无引导，示例值陷阱
- `investmentPlan.ts:158-172` 的 `emptyProfile()` 直接填好 10 万资产/1.5 万收入/8 年期限，UI 写"改动实时重算，无需保存"（`InvestmentMapPage.tsx:71`）。零基础用户会误以为这是自己的数据，或对着一堆数字框不知道从哪下手。有静态 5 步地图（`MapNav.tsx`），但没有首次向导、空状态、进度保存。

#### P1-5 板块轮动整页写死演示数据
- `useSectorRotationStore.ts:50-75` 热度/涨跌/资金流全是静态常量，每 5 分钟"刷新"同一批数。虽有 DemoBanner，普通用户仍容易当真。

#### P1-6 术语密集、解释不到位
- rhythm 面板做得好（explanation/howTo/pitfall 三重解释），但 sentiment/macro/fundflow 的 VIX、HY OAS、期限利差、Z-score、Gamma 敞口、NAAIM 等术语几乎无通俗解释。用户看到"真实数据"也转化不成行动。

#### P1-7 演示值与真实值混排，可信度被稀释
- `src/data/mock.ts` 大量写死常量；macro 代理失败时静默回退 mock。用户无法一眼分清哪些能信。

### P2 · 体验与技术债

| 编号 | 问题 | 证据 |
|---|---|---|
| P2-8 | 仓位计算器/技术分析仍要求懂止损价、看 K 线，把用户拉回"交易员"语境 | `PositionSizer.tsx:18-44` |
| P2-9 | UI 风格割裂：内核深色紧凑，外壳白底大字旧风 | `PortfolioPage.tsx:171` vs `App.tsx:67` |
| P2-10 | ConvexTrade 需出海代理，国内普通人默认拿不到完整数据 | README.md:54-69 |
| P2-11 | TS 未开 strict；`fetchStockCandles` 的 `includes(NaN)` 校验恒为 false | `tsconfig.app.json`、`api.ts:292/354` |
| P2-12 | 死代码大面积存在（WS 链路、mock 兜底、无调用 store 方法） | 全局搜索无引用 |

## 3. 优化方案（分阶段，模块化落地）

> **设计原则**（遵守你一贯的模块化偏好）：
> 1. 每个改动做成**独立函数/hook/服务**，通过明确接口接入，不做级联重构；
> 2. 优先"接通已有能力"，其次才是"新建能力"；
> 3. 守住合规边界：不荐股、不给目标价、不预测收益，所有输出仍是通用框架；
> 4. 每阶段可独立验收、独立回滚。

### 阶段一：接通三条 P0（约 2-3 人日，最高优先级）

#### 改动 1：告警自动触发接线
- **新增模块**：`src/services/alertEngine.ts`（独立，不碰 UI）
  - `evaluateAlerts(quotes: Quote[], alerts: Alert[]): Alert[]` —— 纯函数，输入行情快照和告警列表，输出已触发列表。把 `useAlertStore.checkAlert` 里的 switch 判断逻辑迁进来，便于单测。
  - `notifyTriggered(alert): Promise<void>` —— 桌面通知 + 声音，内部做资源存在性兜底（见下）。
- **接入点**：`App.tsx:52-60` 的全局轮询后，加一个 `useEffect`：加载告警 → 按告警里的 symbol 批量取行情（`fetchTencentQuotes()` 已存在，`api.ts:481`）→ 调 `evaluateAlerts` → 对触发项写库 + 通知。
- **资源兜底**：`/alert.mp3`、`/icon.png` 缺失。两个选择（二选一，建议 A）：
  - **A（推荐）**：不依赖外部文件——用 Web Audio API 生成一声短 beep 替代 mp3；通知图标改用项目已有的 `/icons.svg` 或省略。
  - **B**：往 `public/` 补一个极小的 mp3 和 png，重新 `npm run build`。
- **额外修**：`checkAlert` 里 `forEach(async ...)` 并行写库无错误处理（`:118`），改为 `for...of` 串行 + try/catch。
- **验收**：设一条"价格低于 0"的必然触发告警，30 秒内收到桌面通知，且刷新后告警显示"已触发"。

#### 改动 2：持仓现价自动刷新 + 盈亏计算修复
- **新增模块**：`src/services/portfolioPricing.ts`（独立）
  - `refreshPositions(positions, quotes): Position[]` —— 纯函数，按 symbol 匹配现价，重算 pnl/pnlPercent/marketValue/updatedAt。
  - `computeDayPnL(positions, prevCloses): number` —— 用日线接口（`fetchStockCandles` 已有）取昨收，算出当日盈亏，替换硬编码 0。
  - `computeWinRate(trades): number` —— 从 `TradeRecord` 里配对买卖，算已实现胜率，替换硬编码 0。
- **接入点**：`App.tsx` 轮询后，对持仓 symbol 批量取价 → `usePortfolioStore.refreshFromQuotes()`（在 store 里新增一个 action，复用 `updatePrice` 的计算逻辑，改为批量）。
- **UI 补口**：持仓页现价改为"自动刷新"展示，保留一个手动"刷新价格"按钮兜底；现金余额改为可设置（初始 10 万硬编码 `usePortfolioStore.ts:61` 应来自用户画像的 `investableAssets`）。
- **验收**：添加一条持仓后不做任何操作，观察 30 秒内现价与盈亏随行情变化；`dayPnL` 不再是 0。

#### 改动 3：一键备份/导入（数据安全）
- **新增模块**：`src/services/backup.ts`（独立）
  - `exportAll(): Promise<BackupFile>` —— 汇总 localStorage 各 key（画像、复盘、当日计划、上次市场状态）+ IndexedDB 四张表（持仓、交易、告警、其他），输出统一 JSON。
  - `importAll(file: BackupFile, mode: 'merge'|'replace'): Promise<void>` —— 校验版本/结构后写回，默认 merge，replace 需二次确认。
  - `BackupFile` 结构示例：
    ```json
    {
      "schema": "marvis-backup",
      "version": 1,
      "exportedAt": "2026-11-24T16:00:00+08:00",
      "local": { "profile": {...}, "journal": [...], "regimeLast": {...} },
      "indexedDB": { "positions": [...], "trades": [...], "alerts": [...] }
    }
    ```
- **入口**：在 `App.tsx` 顶栏右上角加一个"数据"按钮 → 弹窗含"导出备份 / 导入备份 / 清空数据"。移动端点此也能用。
- **隐私**：全程本机 File API，不上传；导入前显示"将恢复 N 条持仓、M 条复盘"预览。
- **验收**：导出 JSON → 清空浏览器数据 → 导入 → 所有持仓/复盘/告警逐条恢复。

### 阶段二：首次体验与数据可信度（约 3-4 人日）

#### 改动 4：首次使用向导（onboarding）
- **新增模块**：`src/modules/map/components/Onboarding.tsx`
- 3 屏流程：①"这个工具做什么/不做什么"（明确不荐股）→ ②"先填 3 个关键数字"（可投资资产、月结余、期限，配大白话解释）→ ③"你的第一步：先看能投多少钱"。
- 用 `localStorage` key `marvis.onboarding.done.v1` 记录完成状态；完成后进入 map 页并高亮"下一步"。
- **示例值处理**：`emptyProfile()` 保留示例值但 UI 顶部加醒目黄条"当前是示例数据，请点【改成我的】填写真实情况"，并提供一键清空为 0 的选项。

#### 改动 5：板块轮动去伪装
- **二选一**：
  - **A（省事）**：把 DemoBanner 从页脚小字改成覆盖全屏的醒目"教学示例 / 非实时数据"水印，所有数字加 `~` 前缀。
  - **B（推荐）**：接东财板块资金流接口（`api.ts` 已有 `emGet` 基础设施）换成真实数据，取不到则整页显示"数据不可用"。
- **验收**：随便找个用户，问"这个热度 92 是真的吗"，能一眼答对。

#### 改动 6：术语解释下沉
- 复用 rhythm 的 "explanation / howTo / pitfall" 三件套，抽成公共组件 `SourceExplainer.tsx`，在 sentiment/macro/fundflow 的每个专业指标旁挂一句"是什么 + 对普通人意味着什么 + 常见误读"。
- 不新增术语，纯补解释文本，模块化解耦。

#### 改动 7：消除伪实时
- `useMarketStore.ts`：取不到数据时把 `spx/vix` 置为 `null`，UI 显示"—"，`lastUpdate` 仅在成功时更新。与 rhythm 的"拒绝编造"保持一致。

### 阶段三：体验统一与技术债（约 3-5 人日，可增量）

| 改动 | 做法 | 影响范围 |
|---|---|---|
| 8. UI 风格统一 | 抽公共 `theme.ts` 色板/字号 token，portfolio/technical/papertrading/alerts 改用深色紧凑风 | 4 个页面，纯样式 |
| 9. 死代码清理 | 删除未引用的 WS/mock 链路；保留者加注释说明用途 | 独立文件，不影响主流程 |

## 5. 明确不做（守住定位）

- ❌ 不做荐股、目标价、买卖点、收益承诺——这是产品合规红线，也是它与行情终端的根本区别。
- ❌ 不做自动交易/券商对接——持仓保持手动记账。
- ❌ 不为了"数据 100% 真实"而牺牲稳定性——取不到就明确显示"不可用"，比编造更可信。
- ❌ 不一次性大重构——所有改动模块化、可独立回滚。

## 6. 给你的落地清单（可照着做）

1. **先决策**：确认是否按"阶段一三条 P0 → 向导 → 其余"的顺序；这是本方案的核心建议。
2. **建分支**：`git checkout -b feat/usability-p0`，一次只做一条改动，做完即验收。
3. **改动 3 起步**（备份）：因为改动 1/2 会动数据结构，先有备份兜底最安全。
4. **每条改动配一个最小验收用例**：写在 `docs/` 里，别只靠肉眼。
5. **上线前跑**：`npm run build` + `npm run lint`，确认 `strict` 之前先保持现状通过，strict 单独立项。
