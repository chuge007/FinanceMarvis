# 后端与整体架构重构（2026-11-26）

> 一句话：把「前端各自直连上游 + 单文件转发壳」换成「本地数据平台 + 服务层 + 产品层」，
> 数据从「每次刷新现抓」变成「落库 + 回填 + 派生因子」，每个数字都带来源与数据日期。

```
│ 产品层  React 19                                           │

│ 统一 client + React Query（staleTime 分级）                │

┌───────────────────────▼─────────────────────────────────┐

│  api/        series · snapshot · factors · regime · health │
│  compute/    分位 · Z · 相关性 · 比价 · 环境分数            │
│  jobs/       调度（单源串行、全局并发 4、失败退避）           │
│  http/       router · respond · middleware · static        │
└───────────────────────┬─────────────────────────────────┘
                        │ 适配器契约（SeriesDef / SnapshotDef）
┌───────────────────────▼─────────────────────────────────┐
│ 数据平台                                                  │
│  data/     SQLite（node:sqlite）→ JSONL 兜底               │
│  adapters/ FRED · 财政部 · Yahoo · 腾讯 · 东财 · CBOE …     │
│  upstream/ registry（单一真源）· transport · forward        │
└───────────────────────┬─────────────────────────────────┘
                        │ 直连 / 出海代理（CONNECT 隧道）
                     上游数据源
```

### 三份重复的路由怎么消除

`server/upstream/registry.mjs` 成为唯一定义点：

- dev → `vite.config.ts` 读它生成 `server.proxy`
- 生产 → `server/app.mjs` 读它做转发
- exe → `launcher.cjs` 解压 `server/` 后复用同一份
- 前端 → `scripts/gen-source-registry.mjs` 生成 `src/core/data/registry.generated.ts`

### exe 形态怎么复用同一份服务端代码

SEA 不能 `require` 外部 ESM。做法：打包时把 `server/**/*.mjs` 一起塞进 assets，
启动时解压到 `%TEMP%/marvis-runtime/server/`，再 `import()` 其中的 `index.mjs`，
调用其导出的 `bootstrap()`。于是 dev / 生产 / exe 跑的是同一份代码，不再是两份。

## 3. 数据纪律（落到了接口形状里）

来自万象/market-fin-data 的硬约束，全部变成机制而非文档：

| 纪律 | 落地方式 |
|---|---|
| 每个数字标数据日期 | 响应信封 `meta.asOf`，前端统一 `asOfLabel()` |
| 禁止跨源混口径 | `meta.source` 单值；同一序列只由一个适配器写库 |
| 取不到要明说「不可得」 | `meta.missing[]`，前端渲染为「不可得」而非 0 或空白 |
| 主备链降级要标注 | `meta.degraded` / `meta.stale`，页面显示「降级 / 陈旧」 |
| 关键数字双源交叉 | FRED 与财政部曲线各自入库，比价与分位在 compute 层对齐 |
| 配额耗尽不重试烧额度 | 429/402 立即进入冷却，调度器退避 |

## 6. 产品信息架构

四个入口 → 五个入口，每个入口只回答一个问题：

| 入口 | 回答的问题 | 内容 |
|---|---|---|
| **今日** | 今天要不要动 | 环境分数环 + 四档信号 + 核心驱动贡献 + 商品比价 + 数据缺口 |
| **地形** | 钱的价格在哪 | 原地图页，右上补「数据覆盖 / 更新时间」 |
| **研究** | 结构如何 | 叠加走势、相关性、板块结构、产业链 |
| **决策** | 做什么动作 | 观察、资金流、工具箱、持仓与复盘 |
| **档案** | 数字从哪来 | 数据平台（库统计 + 源健康 + 覆盖区间）、旧版快照血缘、决策日志 |
| 设置（顶栏） | 能力边界 | 形态、驱动、序列目录、可选通道状态、手动刷新 |

设计取向：不重造视觉语言，延续深色终端风格；新增页面字号统一 ≥0.8125rem（1920 下实测 ≥12px）。

## 8.1 源失效之后系统做什么（不只是标注「不可得」）

1. **同序列主备链**：适配器可返回 `{ points, source }`，腾讯失败自动落东财，成功后把实际来源写进 `series.source` 与健康度记录（`已降级到 xxx`）。
2. **指数退避重试**：连续失败按 2^n×30s 退避，上限 30 分钟，不烧配额。
3. **连续失败计数**：`/api/v1/health` 返回每源 `consecutiveFailures`；≥2 轮时 `meta.degraded=true` 并附 `missing` 文案，今日页缺口区与档案页同时可见「连续 N 轮失败」。
4. **探源命令**：`npm run probe`（可加 `--verbose`/`--source=`/`--ids=`）只抓不写库，输出每源可用比例与失败原因，退出码非 0 可直接接 CI。
5. **口径诚实降级**：拿不到个股涨跌家数时，宽度改用「31 个行业板块涨跌分布」，并把口径写进 label 与 `caliber`，不冒充个股家数。
