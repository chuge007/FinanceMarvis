# 金融数据融合方案（2026-11-27）

> 视角：数据架构 + 交付评审 ｜ 性质：可评审、可直接照着实施 ｜ 范围：21 个开源金融数据项目的融合归位
>
> 一句话结论：**融合 ≠ 全部接入**。21 个项目按「稳定性分级 + 唯一主源」归位到四层架构里：能直连的直连、必须 Key 的走 Key 通道、必须 Python 的走独立数据侧车、回测与交易框架只在工具层登记。每条数据只有一个主源，取最稳定者；主源不可达时按固定降级链下探，拿不到就显示「缺」。

### 硬约束（全文有效，实施时不得违反）

1. 每条数据必须有**唯一主源**，且该主源必须是同品类中**稳定性最高**的可用源。
2. 爬虫类库（S4）**不得**做财务主源、**不得**参与回测口径。
3. **不把 Python 内嵌进 exe**；Python 能力只经独立数据侧车提供。
4. 无数据**一律显示「缺」**，不用模拟值、不用演示常量兜底、不用插值填充。
5. 回测与交易框架**只登记不接入**，**不荐股**、不给目标价、不构成投资建议。
6. **不新增一级导航页面**；所有新增展示落在既有「数据 / 档案」页。
7. 全文档路径使用 **Windows 反斜杠**格式（如 `D:\FinanceMarvis\server\adapters\optional.mjs`）。
8. 同类数据冲突时按第 2.3 节裁决顺序（稳定性 > 当前可达性 > 覆盖广度 > 接入成本）一次性定论，不在实施期临时改判。
9. 任何「登记但未接入」的条目必须带 `status=planned` 或 `role=external-only`，不得伪装成已接入。

## 2. 稳定性判定标准

### 2.1 六级稳定性分级（S1–S6）

| 等级 | 定义 | 判定要点 | 本次归入的项目 / 源 |
|---|---|---|---|
| **S1** 官方协议 / 官方文件 | 数据由权威机构以官方接口、官方 CSV、官方归档形式提供，字段与发布节奏由机构背书 | 有官方文档、有稳定 URL、有发布日历；可长周期缓存与回补 | SEC EDGAR（10-K/Q/8-K/13F）、FRED 官方 API（fredapi 封装的是 FRED 官方 API，属官方一手数据，库只是客户端）、FRED 官方 CSV、美国财政部收益率曲线 CSV、CFTC COT、日本财务省 JGB CSV、BIS、世界银行、CBOE 每日统计、美联储官网日历、人民银行 / 国家统计局 |
| **S2** 官方 API + Key | 商业或机构 API，需 Key，有配额与 SLA 承诺，字段版本化 | 有 Key、有配额、有错误码语义（如 402/429）、有版本号 | Tushare Pro、FMP（含 Alpha Vantage / Twelve Data 同类）、DataBull、Nasdaq Data Link |
| **S3** 免密直连且结构稳定可缓存 | 无 Key，接口结构长期稳定，允许按 TTL 缓存并落库回补 | 弱 SLA 但格式稳定、无风控高频拦截 | baostock（K 线，一级备源）、ccxt（底层直接调用交易所官方 REST/WS 公共接口，库本身不是数据聚合层，稳定性取决于所选交易所）、DefiLlama 稳定币、Yahoo 之外的部分官方 CSV 镜像 |
| **S4** 第三方爬虫封装 | 库本身是网页抓取的集合，源站改版即失效，无 PIT 锚点、无 SLA | 返回 DataFrame、接口数量极大、字段随源站变动；限流/IP 风控常见 | AkShare、ADATA、efinance、yfinance、yahooquery、pytdx / mootdx（依赖本机行情服务器） |
| **S5** 聚合中间件 | 本身不产数据，聚合多家 provider；稳定性取决于底层 provider，且多一层故障点 | 提供统一 SDK / CLI / REST，provider 可切换 | OpenBB、pandas-datareader（S5 只收「本身不产数据、聚合多家 provider」的中间件；直连交易所官方接口的 ccxt 不计入 S5） |
| **S6** 停更或已失效 | 已停止维护，或实测接口已下线 | 仓库停更公告 / 实测 404 / 实测连接重置 | Backtrader（停更）、pyfolio / empyrical（停更）、ConvexTrade（公开 API 已下线，409 类实测失败） |

> 工具类（回测 / 交易 / 组合分析框架）**不参与 S 分级**，统一标「工具」；它们不承载数据项，只登记能力与边界。

### 2.2 「同类数据取最稳定」判定规则

对同一数据项存在多个候选源时，按以下顺序逐条判：

1. **先比 S 级**：S1 > S2 > S3 > S4 > S5 > S6。高者为主源。
2. **级差 ≥2 时强制换主**：即使低稳定源已在运行、实现更省事，也必须把高稳定源升为唯一主源，低者降为一级备源。
3. **级差 =1 时允许现状延续**：现有可运行实现可继续担任主源，但必须在第 4 节标注「可升主」并进入复评清单，不得沉默。
4. **同级比较：可达性 → 覆盖广度 → 接入成本**（见 2.3）。
5. **主源必须是「可持续取到」的**：若主源依赖 Key 且用户未配置 Key，则该数据项按「主源未就绪」处理——降级到一级备源，并在健康条点名「主源未就绪」，**不得静默把备源当主源汇报**。
6. **一条数据只能有一个主源**：禁止「A 抓一半、B 抓一半」的混源拼装；补字段（如 PE、市值）必须标注该字段的来源与口径，且不得跨源参与同一统计量（如分位数、相关系数、回测）。

### 2.3 冲突裁决顺序

当两源都可用、数值不一致时，按下表顺序裁决，**不临场商量**：

| 顺位 | 判据 | 说明 |
|---|---|---|
| 1 | **稳定性**（S 级） | 官方一手 > 带 Key 的商业 API > 免密稳定直连 > 爬虫封装 > 聚合中间件 > 停更失效 |
| 2 | **当前可达性** | 在同一 S 级内，以当前网络与账号条件下稳定可达者为先（需代理可接受，但必须标注 `viaProxy`） |
| 3 | **覆盖广度** | 前两项同级时，取品类覆盖更全者，减少跨源拼接 |
| 4 | **接入成本** | 前三项同级时，取不新增依赖、不改代理、不改前端的方案 |

### 2.4 S4 类不得承担财务主源与回测口径的理由

| 理由 | 具体表现 | 后果 |
|---|---|---|
| **无 PIT 锚点** | AkShare / ADATA / efinance 的财务数据只给报表期，不给**公告日**（`ann_date`） | 回测在「财报已发布」时点用了「尚未公布」的数据，产生未来函数，回测收益虚高且不可复现 |
| **无版本与修订** | 爬虫直接抓页面现值，不保留历史修订 | 同一报表期在不同时间抓到的数值可能不同，无法审计 |
| **字段口径随页面变动** | 源站改版即字段改名、单位变化（万元/亿元）、口径变化（合并/母公司） | 跨期比较失真，且失败是**静默**的（拿到数但口径错） |
| **无 SLA 与限流契约** | 无配额说明、随时可能 IP 风控 | 主源不可用会导致财务页大面积空白，业务连续性无保障 |
| **无公告日即无「可得时点」** | 无法构造 `as-of` 时间轴 | 任何依赖「当时能看到什么」的策略与指标全部失效 |

**结论**：S4 类库可以做**展示型补充**（补字段、补特色品类如龙虎榜/基金净值），但：①不得做财务主源；②不得参与回测与绩效口径；③必须与主源数据**分列展示**，不得混算。

### 5.2 各层失败时的降级路径

| 层 | 失败场景 | 降级路径（按序） | 最终落点 |
|---|---|---|---|
| L1 | FRED 直连超时 / 被墙 | ① `/fred` 直连 → ② `/fred-proxy`（出海代理） | 两条皆失败 → 显示「缺」 |
| L1 | Yahoo `query1` 403 / 限流 | ① `query1` → ② `query2`（同 adapters 内已实现） | 皆失败 → 高价值重点品种落到 FMP（若已配 Key）；其余品种直接「缺」 |
| L1 | 腾讯 K 线为空 / 被拦截 | ① `tencent-web` → ② `eastmoney-kline`（内部降级，已实现） | 皆失败 → 显示「缺」，并在健康条点名 |
| L1 | 腾讯行业榜为空 | ① 腾讯行业榜 → ② `sina-sector`（仅当日价格） | 皆失败 → 显示「缺」 |
| L1 | 美股快照 | 腾讯美股快照**已停更**，直接跳过 → 显示「缺」 | 不得当备源 |
| L2 | FMP 402（时点配额耗尽）/ 429 | 立即降级到 Yahoo EOD（高价值重点品种与其余品种一律回落 Yahoo），**不重试**；隔 1–2 小时单点探测复活 | 皆失败 → 显示「缺」 |
| L2 | Tushare 积分 / 权限不足 | 降级到备源（AkShare 仅展示字段），**财务主源缺失数据不补假值** | 显示「缺」并提示权限不足 |
| L2 | 用户未填 Key | 整条 Key 链路在装配阶段摘除（`createOptionalSeries` 不注册） | 数据项显示「缺」+「在设置里填入 X 后启用」 |
| L3 | Python 未安装 / 版本 < 3.11 | 侧车 capability `available: false`，`probe` 返回不可用 | 相关数据项显示「缺」，并给出安装命令 |
| L3 | 侧车进程崩溃 / 端口占用 | 连续失败 3 次冷却 10 分钟；in-flight 请求返回 `SIDECAR_DOWN` | 显示「缺」，健康条「data-sidecar：不可用」 |
| L3 | 单库导入失败（如仅 akshare 装好） | `health` 按库返回 `libs` 明细，未装的库方法返回 `LIB_UNAVAILABLE` | 只有该库相关数据项显示「缺」，不影响其他库 |
| L4 | 无数据（本就是登记层） | 不存在降级 | 页面说明「仅登记、不接入」 |
