## 2. 数据资产分类体系

### 2.1 设计原则

1. **主维度只有一个**：数据资产域（Domain）。避免同时用「市场」和「类型」切两刀造成同一数据两处存放。
2. **交叉标签复用现有轴**：现有 `cadence × kind × chain` 已在 `src/core/data/sourceCatalog.ts` 落地，不推倒重来，只补必要轴。
3. **不与 11 项导航打架**：导航是「投研动作」，分类是「数据资产」，两者正交。新分类只在「数据 / 档案」两个页落点，**不新增一级导航**。
4. **角色编码选型结论**：`primary / backup / fallback / external-only / tool` 作为标签，页面上直接显示，选型结论对用户可见。

### 2.2 主维度：9 个数据资产域

## 4. Python sidecar 架构设计

### 4.1 为什么独立一个 sidecar

现有 `server/local/sidecar.mjs` 是**富途 OpenD 专用**：stdio JSON-RPC、方法白名单、懒启动、6s ping。它有两个不适合复用的点：

1. 富途侧车依赖 `futu-api`，若该库导入失败，整个进程不可用；把 AkShare/EDGAR/ccxt 塞进去会被富途依赖连坐。
2. stdio 是**串行**通道，而 AkShare 网页抓取慢、EDGAR 批量下载大，会阻塞富途实时请求。

**结论**：新建独立数据侧车 `sidecar/data_main.py`，走 **HTTP 回环**（127.0.0.1），与富途侧车共用「懒启动 + 白名单 + 超时 + 失败冷却」的生命周期约定，但进程隔离。

### 4.2 架构与调用链

```
前端 /api/v1/* 或旧 services
        │
        ▼
server/services.mjs ──► adapters/dataSidecar.mjs（SeriesDef / SnapshotDef）
        │                       │
        │                       ▼ transport.fetch('/sidecar-data/<method>')
        │              ┌────────────────────────────┐
        │              │ server/upstream/registry.mjs│
        │              │ id: 'sidecar-data'          │
        │              │ prefix: '/sidecar-data'     │
        │              │ origin: http://127.0.0.1:8765│
        │              │ auth: 'client', egress:'cn' │
        │              │ priority: 'P2', ttl: 600    │
        │              └────────────────────────────┘
        │                       │
        │                       ▼
        │              sidecar/data_main.py（HTTP，绑定 127.0.0.1）
        │              ├─ akshare.*   （特色品类）
        │              ├─ edgar.*     （SEC 文件）
        │              └─ ccxt.*      （加密行情）
        ▼
server/data/db.mjs（SQLite → JSONL 降级，%APPDATA%/Marvis）
```

**关键点**：sidecar 的 HTTP 前缀必须进 `registry.mjs`（唯一真源），这样 dev 的 `vite.config.ts`、exe 的转发、前端 `registry.generated.ts` 三处自动一致；**不另建独立代理**。

### 4.3 生命周期与端口

| 项 | 设计 |
|---|---|
| 启动 | 懒启动：首次 `/sidecar-data/*` 请求触发；exe 下脚本路径由 launcher 注入 `MARVIS_DATA_SIDECAR_SCRIPT`（对齐现有 `MARVIS_SIDECAR_SCRIPT`） |
| 解释器 | `MARVIS_PYTHON` 指定，默认 `python`；启动时校验 `sys.version >= 3.11`（AkShare 硬要求） |
| 端口 | 默认 `8765`，可用 `MARVIS_SIDECAR_DATA_PORT` 覆盖；**只绑定 127.0.0.1**，不对外 |
| 健康探测 | `GET /health` 返回每个库的 `importable` 状态与版本；Node 侧 30s 缓存结果 |
| 超时 | 单请求 20s（对齐现有 sidecar），批量 EDGAR 下载单独放宽到 60s |
| 并发 | 同方法串行（AkShare 爬虫易触发风控）；不同方法最多 2 并发；复用 `server/jobs/scheduler.mjs` 的并发闸门思路 |
| 失败冷却 | 同一方法连续失败 3 次后冷却 10 分钟；期间直接返回「缺」 |
| 退出 | 空闲 10 分钟自动退出；`server/app.mjs` 关闭时发 `POST /shutdown`；进程异常退出时所有 in-flight 请求返回 `SIDECAR_DOWN` |
| 缓存 | registry TTL 600s + `server/data/db.mjs` 历史库；AkShare 结果**必须落库**，避免反复抓同一网页 |

### 4.4 依赖安装与 exe 分发取舍

| 方案 | 优 | 劣 | 结论 |
|---|---|---|---|
| Python 内嵌进 exe | 双击即用 |体积 +100MB 起、Python 版本与库冲突、许可复杂、更新困难 | **否** |
| 复用用户本机 Python | 零体积、用户可控版本 | 需用户装 Python 与库 | **是** |
| 随包带安装脚本 | 安装路径清晰 | 需用户操作一次 | **是**（配套） |

落地要求：

- 新增 `sidecar/requirements-data.txt`（`akshare`、`sec-edgar-downloader`/`edgartools`、`ccxt`，版本锁定），与现有 `sidecar/requirements.txt`（futu-api）**分开**，避免装一个失败连坐另一个。
- 新增一键安装入口（Windows bat）：`py -3.11 -m pip install -r sidecar/requirements-data.txt`。
- 设置页与数据健康条显示「数据侧车：未安装 / 可用 / 部分库不可用」，并给出安装命令；**没有 Python 时相关源显示「缺」，绝不模拟**。
- `desktop/make-exe.mjs` 的 `sidecarFiles` 收集规则（`*.py` + `requirements.txt`）需扩展为同时收 `requirements-data.txt`；`desktop/launcher.cjs` 注入 `MARVIS_DATA_SIDECAR_SCRIPT`（沿用现有注入模式）。

### 4.5 registry 接入点（实施清单）

1. `server/upstream/registry.mjs` 新增 `sidecar-data` 条目（字段见 4.2 注释），并在 `upstreamManifest()` 输出 `domain/role/quality`。
2. `server/config.mjs` 的 `clients` 增加 `dataSidecar: '127.0.0.1:8765'`，`keys` 增加 `fmp: process.env.FMP_API_KEY || ''`。
3. `server/adapters/index.mjs` 的 `capabilities` 增加 `data-sidecar`（探测 `/health`）与 `fmp`（Key 探测），文案沿用「在设置里填入…后启用」格式。
4. 新增 `server/adapters/dataSidecar.mjs`：定义 `SERIES`（AkShare 品类、ccxt 行情）与 `SNAPSHOTS`（EDGAR 文件清单），走统一 `transport`。
5. `scripts/gen-source-registry.mjs` 重跑生成 `src/core/data/registry.generated.ts`。
